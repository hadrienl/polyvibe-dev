Agents, restarts and quitting

Change agent or model without losing the work, put a closed session back to work, and quit without interrupting an agent in the middle of its turn.

Supported agents

Polyvibe runs Claude Code, Codex CLI and Antigravity (agy), each in its own terminal interface, with your account and your configuration. It passes no flag that widens what you allowed your CLI, apart from the automatic approval mode if you choose it, and reads no credential of their accounts. The only key it knows is that of an endpoint you declared yourself. Apart from the approval mode of Codex and Antigravity, what an agent may do inside a session is its own configuration: Polyvibe neither widens nor narrows it.

Two additions are made at launch, for that launch only: the agent's hooks report its activity — working, waiting, finished — once you have approved them (Settings › Agents), and its tool server vibe-browser gives it the web view.

Antigravity's tools show in the conversation as those of the other two do: a command with its output and exit code, a file read, an edit with its diff, a web search, an MCP tool, a question with its answers, a sub-agent with its own transcript.

Approval mode

Codex and Antigravity each have an Approval mode in Settings › Agents: As Set in the CLI, the default, passes nothing: the approval setting of the CLI's own configuration applies. Manual makes the agent ask you: Codex runs with its on-request policy and you as the reviewer, Antigravity in request-review. It replaces the approval setting of the CLI's own configuration. Automatic lets the agent approve its own actions, inside its sandbox, instead of stopping to ask: for Codex it is Approve for me; for Antigravity, its auto mode in the terminal sandbox, which needs a personal Antigravity account. Codex keeps a choice per account and per endpoint it drives; an endpoint driven by Antigravity always runs in Manual. The choice is read again at every launch and restart: a running session keeps the mode it started with.

Several accounts

The same agent can run on several accounts: your personal subscription and your company's, for instance. An account is Claude Code or Codex with its own configuration folder. Antigravity has no additional account: it keeps a single sign-in in the keychain, whatever its folder.

  1. Settings › Add an Account…, below the list of agents.
  2. Choose the agent, give the account a name and set its Configuration Folder. The folder is created if needed.
  3. Sign in from the account's page. It then shows among the agents, when you create a session as in Switch Agent.

A new account starts from nothing: it has neither the MCP servers, the plugins nor the skills of the agent's own account. Add them to its folder.

Each account's page says which account it is signed in to, organisation included. Polyvibe tells you when two agents are signed in to the same account, or when an agent signed in again to an account other than its own: Sign In Again or Keep This Account. Deleting an account removes it from the list; its folder and its conversations stay on the disk.

Agents on an endpoint

An endpoint is a model server reachable over HTTP: on this Mac (Ollama, LM Studio) or in the cloud (OpenRouter, your company's gateway). Its models appear beside the agents when you create a session, and the session runs Claude Code, Codex or Antigravity against them: same terminal, same conversation view, same requests, same resume after a relaunch.

  1. Settings › Endpoints › Add an Endpoint…, then a starting point: Ollama, LM Studio, OpenRouter, or an Other Server. A known server fills in the address, the protocol and the key it expects.
  2. Key: typed once, written to the login keychain (one item per endpoint, never synchronised) and never shown again. Deleting the endpoint deletes it.
  3. Models: Read from the Endpoint lists what the server offers. A model that cannot call tools is kept but not offered: without tools, an agent can read no file. Give each model its real context window.
  4. Driven by: Automatic picks Claude Code or Codex from the server's protocol; you can force Claude Code, Codex or Antigravity. Antigravity reaches the endpoint through Polyvibe's own gateway, without a Google sign-in, and always in Manual mode.
  5. Test sends a short request asking the model to call a tool, and says what worked: reachable, authentication, streamed answer and speed, tool call, answer after the tool, tokens reported. An endpoint whose last test failed is not offered for new sessions.

A server that follows no standard is described with the Custom protocol, in a JSON document: Insert the Example gives one to start from. The format is detailed in docs/endpoints.md.

Switch agent or model

The agent's button in the status bar, under the session, names the agent and model, as in “Claude Code · Opus 5.5”. Its menu shows the agent under its logo, with its state, the history of its switches as a submenu, and Switch To, with the models of each agent under its logo: choose one to open the switch on it, or Other Settings…. Session › Switch Agent… (⌃⌘M) opens the switch too.

In the sheet, choose the agent and its model, then, in the Conversation menu, what the new one starts from.

Change agent or model, and choose what the new one is given.
Continue the conversation
The agent resumes the same conversation with its own resume, and is sent nothing. Offered when the agent stays the same, and chosen by default for a change of model.
New conversation with history
A new conversation, handed copies of the transcripts of every agent the session had — previous accounts and endpoints, sub-agents included — that it reads as it needs. The copies are made once the agent has stopped, so they hold its last turn, and stay on this Mac, readable by you alone, until you delete them: they may hold sensitive information.
New conversation with summary
A new conversation, handed a summary of the session: who worked in it, where the work stands on each branch and worktree, its notes and the prompt it was created with. The summary is shown and editable before it is sent, and never presented as the conversation itself.

History or summary start afresh, even with the same agent. Your choice and your edits to the summary are kept while you try other models.

Nothing is stopped until you confirm with Stop and Switch (⌘Return). If the new agent fails to start, the session goes back to its previous agent, resumable as before. Every switch is kept in the session's history, and the conversation view keeps reading the transcripts of every agent the session had.

Restart a closed session

A closed session shows a bar: “This session is closed. Everything it carries is kept.” Restart — or Session › Restart Session, ⌃⌘R — puts it back to work with the same agent, model, folder and worktree.

A closed session keeps everything, and restarts in one command.
  • When the agent can resume its own conversation, it does, and is sent nothing.
  • When it cannot — no identifier was ever kept, or the CLI would refuse it — the app says so and offers a new process with a summary of the session, shown and editable before it is sent.

A session created with Add to To Do has never run: the same command reads Start Session.

Quit without stopping the agents

Every terminal runs in a terminal host, a background process with no window and no Dock icon. So when agents are working and you quit, Polyvibe asks:

Keep Running
The agents carry on with their turn. At the next launch each one is back on screen as it was, nothing relaunched, nothing sent; one that finished meanwhile shows its last output. Side terminals keep running too.
Stop All
The agents are stopped, and left as the intention to resume them: at the next launch they come back with their CLI's own resume, without asking.

Tick Don't ask again, or choose in Settings › General, to always do the same. Updates use the same choice: an update can be installed while agents keep running.

Restarting or logging out of the Mac stops the agents: Keep Running outlives the app, not your macOS session. At the next launch, sessions are resumed natively.

After a crash

A crash is not an intention: at the next launch, a banner offers Resume Sessions or Ignore, instead of resuming them on its own. Sessions come back one at a time, with progress and a way to cancel; a restoration that would send a text to an agent is never automatic.
