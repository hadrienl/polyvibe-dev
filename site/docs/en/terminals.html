Side terminals and web view

Each session has its own drawer of terminals for a server, a log or a git command, and its own web view that you and the agent both use, simulators and Android phones included.

Side terminals

View › Show Terminals (⌘J), or the terminal button of the status bar, opens a drawer under the session. View › New Terminal (⌘T) adds a tab; with the keyboard in the web view, ⌘T opens a web tab instead. Each tab is a login shell started in the session's folder, titled by the command it runs or the folder it is in.

The drawer of side terminals, under the session.
  • Hiding the drawer stops nothing. A hidden terminal that writes or ends is signalled on the status bar's button.
  • Double-click a tab to rename it; its context menu moves it left or right, or closes it (⌘W with the keyboard in it). ⌃⇥ and ⌃⇧⇥ cycle the tabs.
  • A shell that ended offers to restart or close.
  • Up to eight terminals per session.

The side terminals belong to their session: they stop when it closes, and come back when it reopens or when the app relaunches — same tabs, same order, same folder, what each showed — as new shells under a dated line. Nothing is run again. If you quit with Keep Running, they keep running with their agent.

Their history is the only terminal output written to disk; Settings › General turns it off and erases it.

The web view

View › Show Web View (⌥⌘B), or the globe in the toolbar, opens a browser beside the session, with its own tabs. Switching sessions switches tabs; nothing reloads.

The agent opened its local preview in the session's web view.
  • The Web menu has the usual commands: Open Location… (⌘L), Reload Page (⌘R), Back and Forward (⌘[ ⌘]), Open Page in Browser.
  • The address field also takes a ticket: type #142.
  • The session's ticket is its first pinned tab. It is the one you gave the session, or the one its branch names (feat/142-… on GitHub or GitLab). The More menu sets, changes or removes it.
  • ⌘-click a link in a terminal opens it in the web view, or in your browser — Settings › Web View decides, and ⌥⌘-click does the other.
  • All sessions share one set of cookies, apart from Safari's: sign in to GitHub or GitLab once, and every ticket tab is signed in.

Tabs

Above the page, one button stands for the tabs: the icon and the full title of the tab on screen, and how many tabs there are. Click it for the list, as wide as the web view.

The ticket and the pinned tabs first, then the others.
  • Pinned comes first — the ticket, then the tabs you pinned — and Tabs below. Each row shows its title on two lines and its host; hover over it for its pin and its close button.
  • ↑ ↓ and Return choose a tab, Esc closes the list. New Tab (⌘T) is at its foot.
  • Pin a tab with its pin, with Pin Tab in its context menu, or by dragging it among the pinned ones; dragged below them, it is unpinned. Pinned tabs come back first after a relaunch.
  • Move Up and Move Down, in the context menu, keep a tab in its section. ⌃⇥ goes through the ticket, the pinned tabs, then the others; ⌘W closes a pinned tab too.

Simulators and Android phones

The Simulators button, a phone beside the globe in the toolbar, lists the iOS simulators and the Android emulators running on this Mac, and the Android phones plugged in by USB or already paired over Wi-Fi. Pick one: it opens live in a tab of the web view, and you use it with the mouse.

A simulator in the web view, beside the agent that works on its app.
  • Stop Simulator, in the tab of a simulator or an emulator, shuts it down and closes the tab. A phone has no such button.
  • Simulators need Xcode. Android needs adb, from Android Studio or brew install --cask android-platform-tools, and a phone needs USB debugging, turned on in its Developer options then accepted on the phone. The list says when a phone waits for that, or is offline.
  • For an Android phone, a small screen server, scrcpy's, is copied to it for the time of the mirror. Nothing is installed on a simulator or an emulator.
  • The agent opens one too, with the devices_list and device_open tools of vibe-browser.
  • The iPhone companion shows them as well, by touch.

What the agent can do with it

Each agent is started with a tool server, vibe-browser, that gives it the session's web view: list, open, reload and close tabs, read a page's text or structure, take a screenshot, read the console, click, fill fields and run JavaScript. The agent sees its own session's tabs only. In the terminals, the vibe browser command does the same from a script, and an open https://… run by the agent shows the page here.

When the agent wants to act on another site, a banner in the web view asks: Deny, Allow Once, or Always Allow for that site. The agent waits two minutes at most; the session's row shows a hand meanwhile. The tab the agent opened carries a mark, the element it clicks is outlined, and the Agent Actions log lists what it did.

Before reading a page of another site, the agent asks too: “The agent wants to read a page of github.com.” Allowed, it can read that site until the session ends — what you see there once signed in included; refused, it gets a refusal and no new question. As long as a site is not readable, neither its title nor its full address is given to it. The Agent Actions log lists first the sites the session Can read and those Refused, each with Remove; archiving the session or relaunching the app forgets them too.

  • A tab the agent opened or acted on comes to the front before it loads a remote site, and marks its session's row if that session is not on screen. It stays the agent's until you click or type in it.
  • A download started in an agent's tab is asked; every downloaded file gets macOS's quarantine, in Polyvibe's name.
  • A page that wants to open another application (zoommtg:, x-apple.systempreferences:…) always asks, even after your click; without a click, it is refused.

Once a site is allowed, the agent reads what you see there signed in, a private ticket for instance. Turn off Give agents the web view in Settings › Web View if you do not want that.
